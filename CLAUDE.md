# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

AI-powered CLI (plus a local web page, `--ui`) that scans a directory of documents, clusters them by semantic content similarity (sentence embeddings + KMeans), and moves/organizes files into folders named after cluster keywords (YAKE keyword extraction) — or into the user's existing folders (`--into`).

Project identity: **100% local.** Nothing about the user's files leaves the machine; the only network access is the one-time model download (enforced by `tests/test_quality.py`'s offline guard). Anything that talks to a server must be loopback-only (`--ui` binds 127.0.0.1; `--llm-names` posts to 127.0.0.1:11434 with proxies disabled). See `TODO.md`'s roadmap for why this beats LLM-per-file sorters.

Requires Python 3.12+ (`requires-python` in `pyproject.toml`) — `numpy==2.5.1` has no 3.11 wheels (this is why CI failed at `pip install` until it moved to 3.12); stdlib `tomllib` reads the optional `~/.config/file-organizer.toml` defaults file.

## Commands

Install dependencies:
```bash
pip install -r requirements.txt
```
Or `pip install -e .` (uses `pyproject.toml`) to also get a real `document_analyzer` top-level package and the `organize-files` console script.

Run the CLI (prompts interactively for a directory path if omitted; see `main.py::parse_args` for the full flag set — `--target-dir`, `--dry-run`, `-y`, `--path-weight`, `--max-clusters`, `--folders` (a number or comma-separated names), `--min-files`, `--spaced-names`, `--keyword-ngram`, `--keyword-count`, `--lang` (default `auto`), `--misc-threshold`, `--copy`, `--report`, `--undo` (`last` = newest run not yet undone), `--history`, `--version`, `--include-all`, `--exclude`, `--verbose`/`--quiet`, `--ui`, `--into`, `--plan`/`--apply`, `--depth`, `--llm-names`, `--no-cache`):
```bash
python -m src.document_analyzer.main
```

Run all tests:
```bash
python -m unittest discover tests
```
Quality test with the real embedding model on `examples/demo` (slow, ~470 MB model download the first time; skipped otherwise):
```bash
RUN_QUALITY=1 python -m unittest tests.test_quality
```


Run a single test file / test case / test method:
```bash
python -m unittest tests.test_analyzer
python -m unittest tests.test_analyzer.TestDocumentAnalyzer
python -m unittest tests.test_analyzer.TestDocumentAnalyzer.test_extract_keywords
```

## Architecture

Single pipeline, driven from `src/document_analyzer/analyzer.py::DocumentAnalyzer`:

0. **`DocumentAnalyzer(path_weight=2, max_clusters=10, yake_ngram=2, yake_top=5, skip_noise=True, exclude_patterns=None, lang="auto", misc_threshold=2.0, use_cache=True, depth=1, llm_names=None, min_files=2, spaced_names=False)`** — `use_cache`/`depth`/`llm_names`/`min_files`/`spaced_names` are described below; the model is loaded lazily (`model` property → `_load_model()` on first access), so a run whose embeddings are all cached never loads it. The original tuning knobs are constructor params (also exposed as CLI flags in `main.py`); defaults match the original hardcoded values (`skip_noise`/`exclude_patterns`/`lang` are newer and have no old behavior to match — filtering defaults on, exclude defaults to none, `lang` defaults to the original hardcoded `"en"`). `lang="auto"` (the default) detects each document's language among `AUTO_LANGS` (en, pt, es, fr, de, it, nl); a comma-separated list (`"pt,en"`) restricts detection to those codes. Either way `self.stopword_sets` holds `{lang: YAKE stopword set}` for the candidates; the languages actually found drive per-language centring and the YAKE stopwords (`_stopwords(langs)` unions the lists, since YAKE itself only takes a single `lan`; under auto the extractor is rebuilt in `analyze_directory` after detection). Audio is transcribed during the scan, before detection, so under auto `set_transcription_language` stays `en`; with an explicit list it uses the first code. It reads each list off a throwaway `KeywordExtractor` rather than opening the bundled `.txt` files (their path moved between YAKE 0.4 and 0.7), and returns `None` for a single language so the unchanged path stays entirely inside YAKE. `max_clusters < 3` raises `ValueError` immediately (`_find_optimal_clusters`'s candidate range `range(2, max_k)` is empty otherwise, which used to surface as a bare `numpy`/`sklearn` exception).

1. **`analyze_directory(path, into=None, folders=None)`** — top-level entry point. `folders` comes from `plan.parse_folders` (`--folders`, the UI's "Folders" field). An int skips `_find_optimal_clusters` at the top level only (`_cluster(embeddings, k)`, clamped to the document count; `k_scores` stays `None`) and means *exactly* k folders: `_cluster` skips `_misc_labels` for a given k (sub-levels with `--depth` still pick their own k and keep Misc). A list of names clusters the documents (with `into`, those that fit no archive folder) into exactly `len(names)` groups (`_cluster(..., len(names))`, no Misc, no YAKE) and names each group by `scipy.optimize.linear_sum_assignment` on its *uncentred* centre (`raw`, saved before `_center_by_language` — a bare name has no language group to be centred with) vs `self._embed(names)`, one name per group. Measured on the demo's 8 topics: ARI 0.89 with pt names and with en names; sending each document to its nearest name gave 1.00 in en but 0.75 in pt (uncentred vectors carry the language), so it was dropped. After either, `_keep_stems_together` moves files that share a stem but not an extension (`report.pdf`/`report.docx`) to the folder holding most of them (ties: not Misc, then first). With `spaced_names`, folders named by clustering get `_` → ` ` (never `--into`'s or the user's names). A `Read N entries...` INFO line every 100 entries feeds the UI's progress. With `into`, `_scan_archive(into)` first reads every file under each top-level, non-noise, non-symlink subfolder of `into` (`os.walk`, marker files skipped) as `(folder, text)`; those subfolders (and `into` itself) are then never scanned as documents of `path` (`destinations` set of realpaths), which makes `organize-files ~/Docs --into ~/Docs` sort the loose files into their sibling folders.
   - Scans the directory (`os.scandir`, non-recursive at this level for files, but recurses into subfolders via `_analyze_folder`). Every entry is checked against `_is_noise_entry(name, self.skip_noise, self.exclude_patterns)`: when `skip_noise` (default on), a name starting with `.` or matching `DEFAULT_SKIP_NAMES` (`__pycache__`, `node_modules`) is skipped — this also incidentally hides `organize_files`' own `.file_organizer_created`/`.file_organizer_manifest_*.json` dotfiles from a later scan; `--include-all` (CLI) / `skip_noise=False` (constructor) disables just that default heuristic. Independently, any name matching one of `exclude_patterns` (`fnmatch` glob patterns, `--exclude PATTERN` on the CLI, repeatable) is always skipped, even under `--include-all` — it's an explicit user ask, not the default heuristic. A subfolder is skipped entirely (not recursed, not added as a document) if it's a symlink (`entry.is_symlink()` — prevents unbounded recursion on a symlink cycle) or if it contains `ORGANIZED_MARKER` (`.file_organizer_created`, dropped by `organize_files` into every cluster folder it creates — this stops a second run on an already-organized directory from re-clustering the first run's output as fresh documents); these two checks are unconditional, independent of both `skip_noise` and `exclude_patterns`.
   - Files with extensions in `readable_files` (`.pdf`, `.txt`, `.md`, `.csv`, `.xml`, `.rtf`, `.docx`, `.pptx`, `.odt`, `.xlsx`) get content via `utils.read_file(path, max_chars=READ_CHARS)` (5000 characters: the model only sees ~512 tokens, and reading whole PDFs was 181 s of a 411 s run on ~2000 files; `_analyze_folder` likewise stops reading file contents once a subfolder has `READ_CHARS` of text); extensions in `audio_files` (`.mp3`, `.wav`, `.flac`, `.aac`, `.ogg`, `.wma`, `.m4a`, `.aiff`, `.opus`) get content via `utils.read_audio_metadata`; extensions in `image_files` (`.png`, `.jpg`, `.jpeg`, `.tif`, `.tiff`, `.bmp`, `.webp`) get `utils.ocr_image` (`None` without tesseract); everything else gets `Content: None`. Extension matching is case-insensitive (`ext.lower()`). After the scan, the number of PDFs whose content came back `""` (no text layer, even after OCR) is logged, with a hint to install tesseract when it's missing. This dispatch lives in one module-level helper, `_read_content(full_path)` (returns the text or `None`, logging a warning on a read failure), shared by the top-level scan and `_analyze_folder`.
   - Builds a `pandas.DataFrame` with one row per top-level entry (`Path`, `Content`).
   - `utils.create_weighted_text` concatenates the filename (repeated `self.path_weight` times) with file content into a `Text` column — this weighting biases embeddings toward filename similarity, not just content.
   - Embeds `Text` plus the archive texts (`self._embed(texts)`, one call so both are centred together below) with the model from `_load_model()`: `embed.Embedder(EMBEDDING_MODEL, EMBEDDING_REVISION, local_files_only=True)`, falling back to a normal (downloading) load only on `OSError` (hub's `LocalEntryNotFoundError` is a `FileNotFoundError`), i.e. nothing cached yet. Without `local_files_only`, `huggingface_hub` sends a HEAD request to huggingface.co on *every* load to check for updates, cached or not — measured: the old `SentenceTransformer(EMBEDDING_MODEL)` call retried huggingface.co a dozen times under the offline guard. The revision is pinned so an upstream update can't silently change clusters; `HF_HUB_DISABLE_TELEMETRY=1` is `setdefault` at the top of `analyzer.py`, before `.embed` imports huggingface_hub (hub reads it at import).
   - **`embed.Embedder`** replaced sentence-transformers (which hard-requires torch): `tokenizers` + `onnxruntime` on the repo's own `onnx/model.onnx`, 512-token truncation, attention-masked mean pooling, always L2-normalized, batches of `BATCH_SIZE = 8` sorted by length. Measured on the demo: cosine 1.00000 to the sentence-transformers vectors for every document, same ARI, same speed, peak memory 1.4 GB vs 1.6 GB (batch 32 was 15% faster but peaked at 2.9 GB), ~130 MB of deps instead of ~900 MB. The int8 `onnx/model_qint8_avx512_vnni.onnx` was 38% faster but only 0.987 cosine — rejected. CPU only.
   - **Embedding cache** (`_embed`): sqlite3 at `CACHE_PATH` (`$XDG_CACHE_HOME/file-organizer/embeddings.sqlite`), table `docs(key, vec, last_seen)`, key = sha256 of `EMBEDDING_MODEL@EMBEDDING_REVISION` + the prefixed text — so it survives `organize_files` moving a file (the text uses only the basename) and needs no invalidation. Only misses go to `encode`; all rows are re-stamped and rows older than `CACHE_MAX_AGE_DAYS` (90) deleted; file chmod 0600 (vectors are derived from content). Any sqlite/OS error only warns (`_open_cache` returns `None`). `use_cache=False` / `--no-cache` bypasses it. ponytail: files are still read every run; only encoding is saved.
   - The model is `intfloat/multilingual-e5-small`, each text prefixed with `EMBEDDING_PREFIX` (`"query: "`, what e5's model card specifies for symmetric tasks like clustering) and normalized so KMeans' Euclidean distance is monotonic in cosine distance, the metric these embeddings are trained for. Two deliberate choices here: multilingual, because the original `all-MiniLM-L6-v2` is English-only and gave non-English documents near-random embeddings; and 512-token context, because `paraphrase-multilingual-MiniLM-L12-v2` truncates at 128 — short enough that every letterheaded PDF (institution header, CNPJ, address) embedded to the same boilerplate and collapsed into one giant cluster. ~470MB download vs `all-MiniLM-L6-v2`'s ~90MB. If you change the model, re-check `max_seq_length` and whether it wants a prefix. Logs an info line before this step and before cluster-count search — both can be slow on larger directories.
   - **Per-language centering** (always runs): `_detect_languages` assigns each `Text` the candidate language whose stopwords it uses most, or `""` when it has none (bare filenames - that group is centred like a language too), and `_center_by_language` subtracts each language's mean embedding and re-normalizes. Without it a pt+en folder clustered by *language* (e5 encodes language more strongly than topic); measured on `examples/demo`'s 64 topic texts, adjusted Rand vs. true topics at k=8 went 0.34 → 1.00. A language with a single document is left uncentred.
   - `_find_optimal_clusters` picks a k (2..min(`self.max_clusters`, n-1), inclusive of both ends) by combining elbow-method (`_elbow_k`: `K[argmax(np.diff(inertia, 2)) + 1]` — it used to be `argmin` without the `+1`, i.e. the flattest stretch, off by one), silhouette score (max), and Davies-Bouldin score (min) — the **median** of the three candidates. Median rather than `Counter.most_common`: with three distinct candidates the counter silently returned whichever was inserted first (silhouette), and silhouette on one dense blob plus a few outliers always votes for a tiny k. The median still returns the majority value whenever two metrics agree. The upper bound is capped at `n - 1` rather than `n` because `silhouette_score` requires strictly fewer clusters than samples (k == n would crash mid-loop). The elbow candidate is only included when there are ≥3 k-values to test (≥5 documents), since a 2nd derivative needs 3+ points; below that it falls back to silhouette/Davies-Bouldin only, and directories with ≤2 usable documents skip clustering entirely (`k=1`, everything in one folder) rather than crashing. Davies-Bouldin replaced Calinski-Harabasz, which voted k=2 on nearly every real folder (so the median collapsed to min(elbow, silhouette)): on the 68-file demo k went 4 → 10, adjusted Rand 0.35 → 0.85.
   - **`--into` assignment** (`_assign_to_folders`): prototype per archive folder = mean of its files' embeddings; a new document goes to its nearest prototype if its distance ≤ mean + `misc_threshold` × std of *all* archive files' distances to their own prototypes (global, like `_misc_labels`, because a 1-2 file folder has no usable spread of its own; `misc_threshold=0` always assigns). Distances via dot products (an n × folders × dim array would be hundreds of MB). Leftovers are clustered as usual (`_cluster` + `_organize_clusters`), except fewer than 3 leftovers all go to `Misc` rather than spawning a new folder next to the user's own. Measured on the demo: 9 of 10 files taken out of an organized copy went back to their folder (the miss came from a folder left with one file).
   - Stores `self.k_scores` (`k`, `inertia`, `silhouette`, `davies_bouldin`, `votes`, `chosen`; `None` for ≤2 docs; the top level's, saved before sub-clustering overwrites it) and `self.last_run` (`paths`, `texts` (for `split_folder`), `embeddings` as clustered, `k_scores`, `scores` = `_file_scores`: per file, cosine to its folder's centroid — the archive prototype for `--into` folders — rounded to 2 places; `sensitive` = `{file: sorted(utils.sensitive_kinds(content))}`, logged as a warning count) for `report.py`, the plan file and the UI.
   - `self._cluster(embeddings)` runs `_find_optimal_clusters`, then `KMeans` with that k, then `_misc_labels`, and returns the labels; `_misc_labels` gives label `-1` to documents farther than mean + `misc_threshold` × std from their centroid, with a negative silhouette (closer to another cluster than their own), or left in a cluster of fewer than `min_files` (2: no one-file folders; `--min-files`) (`misc_threshold=0` disables all of it) → `MISC_FOLDER` (`"Misc"`, no YAKE naming). Then `_organize_clusters(df, embeddings=None, depth=1, parent="")` names each cluster folder via `_cluster_name` → `_folder_name(keywords, taken)` — the top-2 YAKE keywords joined, dropping words the two share (YAKE's top keywords overlap constantly, which used to produce names like `Engenharia_eletrica_energia_eletrica`) and words of the parent folder's name (`taken`: keywords made only of those are skipped, so the next keywords are used; no fallback to the unfiltered name, which produced `Public_license_general/Public_license_general` on 1,970 license texts); falls back to `Cluster_<n>` if nothing is left. If two clusters produce the same folder name, their files are merged into that one folder (`setdefault(...).extend(...)`) rather than one cluster's files overwriting the other's. **`split_folder(name, files)`** (the UI's Split) re-clusters a subset of `last_run` (`_cluster` with automatic k, then `_organize_clusters(..., 1, parent=name)`), so children are `name/Child` and misfits stay in `name`, like `--depth`; returns `(folders, _file_scores(...))`; fewer than 4 files → `ValueError`. `_organize_clusters` splits the parent's words on `_`, `/` and whitespace (UI-typed names have spaces).
   - **Hierarchy** (`depth > 1`, `--depth`): a cluster of `SPLIT_MIN` (20)+ files is re-clustered (`self._cluster` on its subset of the already-centred embeddings) into `"Parent/Child"` folders; a file the lower level labels `-1` stays in `Parent` itself rather than a nested Misc.
   - **Local-LLM names** (`llm_names`, `--llm-names MODEL`): `_llm_folder_name` posts YAKE's keywords plus the 5 file names nearest the cluster's mean to `OLLAMA_URL` (`http://127.0.0.1:11434/api/generate`, hardcoded loopback — no host option, on purpose) through `build_opener(ProxyHandler({}))` (urllib would otherwise honour `http_proxy` even for 127.0.0.1 and hand the keywords to a proxy). The prompt has examples and explicit don'ts (no abbreviations, dates, file names) and the request sets `temperature: 0, seed: 0` — measured with qwen2.5:1.5b: the bare prompt gave `StockExch`/`WorldCup2022` and renamed half the demo's folders between runs. The reply is stripped of `<think>` blocks, split on any non-word character *and* `_`/`-` (so the 3-word cap holds), 3 words / 40 chars max; a name with characters beyond Latin Extended (U+024F) — Qwen drifts into Chinese — or any error → `None` → YAKE's name. One request per cluster.
   - Returns `{folder_name: [original_filenames]}` (folder names may contain `/` with depth > 1).

2. **`_analyze_folder(folder_path)`** — recursively walks a subdirectory, concatenating all descendant file names/contents into a single `Content` blob so the whole subfolder is treated as one document for clustering purposes. Uses `entry.path` directly (never `os.path.join(folder_path, entry)` — `DirEntry.__fspath__` already returns the full path, so joining it again used to double the path and made every subfolder containing a readable/audio file raise `FileNotFoundError`, silently dropping that whole subfolder). Per-file read errors are caught here too, same as the top-level scan in `analyze_directory`, degrading to filename-only instead of losing the rest of the subfolder. Nested symlinked directories are skipped the same way as at the top level, for the same cycle-prevention reason. Applies the same `_is_noise_entry` filtering as the top-level scan, so a nested `.git`/`__pycache__`/`node_modules`/excluded-pattern entry doesn't get folded into the subfolder's content blob either.

3. **`organize_files(folder_structure, source_dir, target_dir=None, copy=False)`** — a `@staticmethod` (also exported as module-level `analyzer.organize_files`), so `--apply` and the UI move files without loading the model. Creates the cluster folders (under `target_dir`, defaulting to `source_dir`) level by level (`"Parent/Child"`), dropping `ORGANIZED_MARKER` only into folders it actually creates — with `--into` the destinations are the user's own folders, which must stay visible to later runs — and moves (`shutil.move`) each original file into its assigned folder — works across filesystems/drives, unlike `os.rename`. This is a real filesystem mutation — moves files out of `source_dir` in place unless `target_dir` is given. Before each move it checks whether the destination path already exists and skips (with a warning) instead of moving — `shutil.move` → `os.rename` on POSIX silently clobbers an existing destination with no error, so the `except FileExistsError` this used to rely on was dead code there (Windows-only). Every successful move is recorded as `{"source": ..., "destination": ...}` and, if anything moved, written as a JSON manifest to `target_dir` (`.file_organizer_manifest_<timestamp>.json`); the method returns that manifest's path (or `None` if nothing moved). **`undo_organize(manifest_path)`** (module-level function, not a method) reads a manifest and moves each destination back to its source, skipping (with a warning) if the destination is missing or the source path is already occupied — mirrors the same never-clobber rule in reverse. With `copy=True` entries are copied (`copy2`/`copytree`) and recorded with `"copy": true`; undo deletes such a copy only while its original still exists. After undoing, cluster folders holding only the marker are removed, walking up from each destination folder so a `Parent/Child` tree goes too (it stops at the first folder holding anything else; a folder without the marker is never removed), and the manifest is deleted if no entry was skipped. Warnings/progress go through `logger`; only the manifest path/undo command and the undo summary are `print`ed.

`src/document_analyzer/utils.py`:
- `read_file(path, max_chars=None)` — dispatches by extension (with `max_chars`, PDFs stop extracting pages and text files stop reading once they have that much): `pypdf` for `.pdf` (its noisy per-object warnings are silenced at import), `_read_zipped_xml(path, member_glob, tags)` driven by `ZIPPED_XML_FORMATS` for `.docx` (`word/document.xml`, `w:t`), `.pptx` (`ppt/slides/slide*.xml` in numeric order, `a:t`) `.odt` (`content.xml`, `text:p`/`text:h`) and `.xlsx` (`xl/*.xml`, spreadsheetml `t` - shared and inline strings) — stdlib only, `_rtf_to_text` for `.rtf` (a small stdlib reader: drops font/colour/info/`\*` groups, decodes `\'hh` and `\uN`), `chardet`-detected-encoding text read (detection on the first 64 KB) for `.txt`/`.md`/`.csv`/`.xml`. Raises on unsupported/unreadable files; empty files return `""`. A PDF with no text layer falls back to `_ocr_pdf(reader, max_chars)`: each page's images (`page.images`) go to a `mkstemp` file and `ocr_image`, until `max_chars`; any exception (e.g. an image format pypdf needs Pillow for) just returns `""`.
- OCR: `TESSERACT = shutil.which("tesseract")` at import (same degrade-to-`None` pattern as ffmpeg/vosk; no Python dependency). `ocr_image(path)` runs `tesseract path stdout -l <_ocr_langs()>` (`lru_cache`d intersection of `tesseract --list-langs` with `TESSERACT_LANGS`, the codes for `AUTO_LANGS`), decodes UTF-8 with `errors="replace"`, and returns `None` below `OCR_MIN_CHARS` (20) so photos don't become noise text.
- `sensitive_kinds(text)` → subset of `{"cpf", "card"}`: CPF regex + both check digits (all-same-digit numbers rejected), card = 13-19 digits (spaces/dashes allowed, no digit on either side) starting 2-6 and passing Luhn (skips ISBNs, which start with 9). CNPJ deliberately not flagged — every letterhead has one. Flag only; ~10% of random digit runs pass Luhn, so it's a hint for a human.
- `create_weighted_text` — the filename/content weighting used for embeddings (see above). Uses the name's words, not the raw filename: extension dropped, separators → spaces (`receita_pao-de.queijo.txt` → `receita pao de queijo`); otherwise YAKE put `feijoada.txt` into folder names. The `path_weight` repetitions are joined with spaces, not concatenated: `"a.pdfa.pdf"` tokenizes as one unknown blob, so the repetition used to add noise rather than weight.
- `read_audio_metadata` — for `audio_files` extensions, combines TinyTag metadata (title/artist/album/genre/composer) with a Vosk offline transcription (via `transcribe_audio`, which shells out to `ffmpeg` to normalize to 16kHz mono WAV first). `TINYTAG_AVAILABLE`/`VOSK_AVAILABLE` are set at import time from `try/except ImportError`, so the whole audio path degrades to `None` (no crash) if `tinytag`/`vosk`/`ffmpeg` aren't installed — those are optional deps in `requirements.txt`. `set_transcription_language(lang_code)` picks from `VOSK_LANGUAGE_MODELS`; models are lazily downloaded to `VOSK_MODEL_DIR` (`~/.cache/vosk`) on first use per language. `DocumentAnalyzer.__init__` calls it with the first `--lang` code. `_convert_to_wav` uses `mkstemp` (not the racy `mktemp`).

`src/document_analyzer/main.py` — CLI wrapper (`argparse`, see `parse_args`): takes `path` as a positional arg (prompted interactively if omitted), builds `DocumentAnalyzer` from the tuning flags, prints the proposed cluster structure, then either stops (`--dry-run`), moves without asking (`-y/--yes`), or asks for `y`/`N` confirmation before calling `organize_files` — nothing moves without an explicit opt-in. `--target-dir` is threaded through to `organize_files`; defaults to `path` (in-place) when omitted. `--undo MANIFEST` short-circuits all of this at the top of `main()` — if passed, it calls `undo_organize` and returns immediately, without touching `path`, `DocumentAnalyzer`, or any tuning flags. `--lang` (default `auto`) is threaded to the `DocumentAnalyzer` constructor (language detection, per-language centring and YAKE stopwords — it never switches the embedding model, which is already multilingual); it takes `auto`, one code or several (`pt,en`). `--history` and `--undo` short-circuit before the analyzer (and its model) is built. `--verbose`/`--quiet` (mutually exclusive) pick the root logging level (`DEBUG`/`WARNING`, default `INFO`); `logging.basicConfig(..., force=True)` is called at the top of `main()` (not at import time) so the level reflects that run's flags — `force=True` matters in-process too, since `basicConfig` is normally a no-op after the first call. `_load_config()` reads `CONFIG_PATH` (`~/.config/file-organizer.toml`, module-level constant so tests can patch it) via stdlib `tomllib` at the top of `parse_args()`, before the parser is built; each `add_argument`'s `default=` pulls from that dict (e.g. `config.get("path_weight", 2)`) so an explicit CLI flag always overrides the config value, and a missing or malformed config file (caught as `tomllib.TOMLDecodeError`/`OSError`, logged as a warning) just falls back to the hardcoded defaults. `--apply FILE` short-circuits like `--undo` (no analyzer built): `_apply_plan` → `plan.read_plan` → `plan.validate_folders` → summary → confirm (or `-y`) → module-level `organize_files`. `--plan FILE` writes `plan.write_plan(...)` after printing the structure and returns (implies dry run). `--into DIR` is passed to `analyze_directory(path, into=...)` and becomes the `organize_files` target (over `--target-dir`). `--ui` builds the analyzer and hands it to `ui.serve` (path optional there). The printed structure appends `[sensitive: cpf]` to flagged files.

`src/document_analyzer/plan.py` — the `--plan` text format (`# organize-files plan<TAB>source=..<TAB>target=..` header, `[Folder]` sections, `score<TAB>file` lines weakest first, `# sensitive: ...` comment lines before flagged files; `#` lines and blank lines ignored, scores optional on read). **`validate_folders(folders, source)`** is the trust boundary for anything user-edited (plan files and the UI's `/api/apply`): rejects folder names with `\`, `:`, or an empty/`.`/`..` path component (so no absolute paths, no escaping the target; `/` allowed for `Parent/Child`), file names with separators or `.`/`..`, files listed twice, and files not present in `source`. **`parse_folders(text)`** reads `--folders`/the UI field: `""` → `None`, digits → int (≥ 1), otherwise comma-separated names, de-duplicated and run through `validate_folders({name: []}, "")` (same name rules as a plan).

`src/document_analyzer/ui.py` + `ui.html` — `--ui`. `make_server(analyzer, path, into, target_dir, copy, folders)` returns a stdlib `ThreadingHTTPServer` on `("127.0.0.1", 0)` and the URL `http://127.0.0.1:<port>/#<token>` (token from `secrets.token_urlsafe`, in the fragment so it's never sent in a request line or logged). Every response carries a strict CSP (`default-src 'none'`, inline script/style only, `connect-src 'self'`). `GET /` serves the page (Host header must be `127.0.0.1:<port>` or `localhost:<port>` — DNS-rebinding guard); every `/api/*` also needs `X-Token` (`secrets.compare_digest`): `GET /api/defaults`, `GET /api/history` (with `undone`), `GET /api/progress` (the latest INFO line of the package logger, kept by the `_Progress` handler `make_server` attaches; no lock, so it answers mid-analysis), `POST /api/analyze {path, into, folders}` (stores source/target and the analyzed file names server-side; returns folders, scores, sensitive, `map` points from `report.tsne_xy` (`[]` below 3 docs or on error) and `suggest` = `{chosen, options}`: the chosen k plus each metric's vote, `null` when the user fixed the folders), `POST /api/preview {file}` (first 600 chars via `analyzer._read_content`), `POST /api/split {name, files}` (`analyzer.split_folder`) — both only for files of the last analysis, `POST /api/apply {folders, copy}` (empty folders dropped, `validate_folders` against the *stored* source — the client can't pick the source dir), `POST /api/undo {manifest}` (only manifests present in `read_history()`). Errors → 400 with `{"error"}`; bodies over 10 MB → 413. A thread per request, but every POST runs under one `threading.Lock`, so they never overlap on the shared analyzer or the state. `serve` prints the URL with `flush=True` (piped stdout is block-buffered and the link is the only way in) and `webbrowser.open`s it. The page builds all user data with `textContent`/`createElement` (no `innerHTML` with data), moves files via a per-file `<select>` (keyboard-accessible, no drag-and-drop), shows a file's preview in a native `<details>`, polls `/api/progress` every second while analyzing, and translates itself to Portuguese when `navigator.language` starts with `pt` (`PT` dict + `t(text, vars)`; static text marked `data-t`, plus `placeholder`/`title`/`aria-label`; server messages stay English), and must contain no `http://`/`https://` string (tested) — hence the SVG namespace is taken from the existing `<svg>` element's `namespaceURI`. `ui.html` ships as package-data (`pyproject.toml`).

`src/document_analyzer/report.py` — `tsne_xy(embeddings)` (2-D t-SNE scaled to [0, 1], cosine, fixed seed; also used by the UI map). `save_report(last_run, folder_structure, out_dir)` for `--report DIR`, sized for a README (~9 in wide at 200 dpi, 11 pt base font, headline + subtitle via `_headline`): `map.png` is one t-SNE map (cosine, fixed seed) with one highlight hue — each folder gets a shaded outline (`_group_outline`: convex hull drawn with a thick round edge; 1-2 or collinear points fall back to a round-capped stroke) and a direct label, Misc files are hollow dots labelled with their names, and `_declutter` nudges overlapping labels upward (more than 3 categorical colours on one scatter fails colour-blind checks, hence no colour per folder). `k_selection.png` has three panels that all vote at their peak: the elbow panel plots the inertia's 2nd difference, and Davies-Bouldin's axis is inverted; the chosen k is a shaded column. `similarity.png` is the cosine heatmap ordered by folder with the diagonal blanked. matplotlib is imported lazily (optional `[viz]` extra). README images are generated with `organize-files examples/demo --dry-run --lang pt,en --report docs/img`; the 68 demo texts (8 topics x 8, pt+en, + 4 one-offs) are Wikipedia excerpts (CC BY-SA, `examples/ATTRIBUTION.md`, kept outside `demo/` so it isn't clustered).

Run history: after writing a manifest, `organize_files` appends a JSON line (time, source/target dirs, manifest, file count, copy) to `HISTORY_PATH` (`$XDG_STATE_HOME/file-organizer/history.jsonl`, default `~/.local/state/...`; failures only warn); `read_history()` returns entries newest first, skipping malformed lines. `main.py --history` prints them with the undo command (or "undone" once the manifest is gone); `--version` reads `importlib.metadata.version("document-analyzer")`, `"dev"` from a checkout. Per-stage timings (read, embed — with how many came from the cache — pick k, name) go to the INFO log; `silhouette_score` samples 2000 documents above that size.

`src/document_analyzer/__init__.py` re-exports `DocumentAnalyzer` so `from document_analyzer import DocumentAnalyzer` works once the package is installed (`pip install -e .`, via `pyproject.toml`).
